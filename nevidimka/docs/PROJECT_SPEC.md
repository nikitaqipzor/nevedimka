## 1. Идея и цель проекта

Личная система роста и дисциплины на 180/365 дней, объединяющая:

- ежедневное планирование и выполнение главной задачи;
- фокус-сессии и доказательства результата;
- AI-наставника, который анализирует поведение, а не просто хранит заметки;
- автоматизированную, но подтверждаемую пользователем публикацию отчётов в закрытый Telegram-канал (текст и видео);
- долгосрочную аналитику (неделя / месяц / 180 дней / год) и карту развития навыков.

Главная цель первой версии — не красивая платформа, а рабочий ежедневный цикл:

```
План → действие → доказательство → анализ → корректировка → следующий день
```

Числа и метрики всегда вычисляются кодом. AI объясняет их и предлагает гипотезы, но не отвечает за арифметику.

## 2. Ключевой принцип: одна система, а не два продукта

Telegram-бот и Mini App/PWA — это **одна система с общим backend и общей базой данных**, а не два независимых проекта:

- Бот — ежедневный интерфейс присутствия: напоминания, короткие взаимодействия, голосовые/видео отчёты, быстрые действия по кнопкам.
- Mini App/PWA — полноценный личный штаб: графики, редактирование плана, карта навыков, дневник, студия контента.

Ни один канал не дублирует бизнес-логику — оба обращаются к одному backend API.

## 3. Архитектура верхнего уровня

```
Telegram-бот (webhook)
        │  напоминания, отчёты, голос/видео, быстрые действия
        ▼
Backend API (единая точка входа)
        │
        ├── База данных (Postgres / Supabase)
        ├── AI-оркестратор (роли наставника)
        ├── Очередь фоновых задач (транскрипция, рендер видео, публикация)
        └── Хранилище файлов (Storage, приватное, с временными ссылками)
        ▼
Mini App / PWA (тот же backend API)
        │  планы, аналитика, дневник, студия контента, настройки
        ▼
Закрытый Telegram-канал
        │  публикация ботом по подтверждению пользователя
        ▼
Пост возвращается в приложение как «доказательство прогресса»
```

Принципы:

- Один backend, один контракт API для бота и Mini App.
- Аутентификация в Mini App — через Telegram initData, проверяемую на сервере.
- Все AI-вызовы идут через backend (ключи API никогда не попадают на клиент).
- Все тяжёлые операции (видео, транскрипция, публикация) — асинхронные фоновые задачи с идемпотентностью и retry.

## 4. Пользовательский путь (ежедневный цикл)

### 4.1 Онбординг (один раз)
1. Приветствие бота, объяснение сути системы.
2. Фиксация «Дня 0»: дата старта, срок (180/365 дней).
3. Договор с собой (текст, который пользователь пишет или надиктовывает).
4. Формулировка одной главной цели (Mission).
5. Выбор направлений: «Создание», «Тело», «Смелость» (или свои).
6. Опционально — сохранение поста «День 0» как первого доказательства пути.

### 4.2 Утро
1. Бот присылает утренний план (текст ниже — пример).
2. Короткий чек-ин: сон, энергия, настроение (1–5 или эмодзи-шкала).
3. Бот показывает главную задачу дня + до 2 дополнительных.
4. Кнопки: `[Начать фокус]` `[Разбить задачу]` `[Изменить план]`.

Пример сообщения:
```
Никита, день 12 из 180.
Вчера главная задача выполнена на 70%.
Сегодня не начинаем ничего нового.
Следующий шаг: закончить сохранение отчёта в базе.
Оценка: 45 минут.

[Начать фокус] [Разбить задачу] [Изменить план]
```

### 4.3 День
- Фокус-сессии (таймер, старт/пауза/стоп, привязка к задаче).
- Приём текстовых, голосовых и видео-отчётов о выполнении.
- Хранилище идей: новая мысль сохраняется в inbox, не прерывая текущую задачу («не разрешаем сразу переключаться»).
- Напоминание о незавершённой задаче через настраиваемый интервал.

### 4.4 Вечер
- Вечерний разбор: что сделано, что перенесено, короткая рефлексия.
- AI формирует план на завтра (черновик, редактируемый пользователем).
- Предложение подготовить пост для закрытого канала на основе дня (опционально).

### 4.5 Срыв и возврат
- Если пользователь пропустил день(-и), бот не наказывает и не обнуляет прогресс.
- Специальный сценарий «возвращения»: короткий безоценочный чек-ин + предложение минимального шага на сегодня.

## 5. Роли AI-наставника

Единый управляемый AI-оркестратор, который делегирует задачи ролям. Каждая роль — это системный промпт + ограниченный набор инструментов + строгий формат ответа.

| Роль | Назначение | Вход | Выход | Подтверждение пользователя |
|---|---|---|---|---|
| Оркестратор | Маршрутизация между ролями | Событие/сообщение | Вызов нужной роли | Нет |
| Стратег | Долгосрочная цель, этапы 180/365 | Mission, история прогресса | Обновлённые этапы | Да, при изменении плана |
| Планировщик дня | Задачи на сегодня | Вчерашний отчёт, чек-ин | 1 главная + до 2 доп. задачи | Да |
| Наставник действий | Разбивка задачи, помощь начать | Задача, затруднение | Подзадачи / первый шаг | Нет |
| Аналитик поведения | Паттерны, переносы, распыление | Метрики за период | Гипотезы, инсайты | Нет |
| Ревьюер результата | Оценка отчёта/доказательства | Отчёт пользователя | Оценка % выполнения, комментарий | Нет |
| Наставник по навыкам | Карта развития навыков | История задач по направлениям | Обновление карты навыков | Нет |
| Редактор текста | Обработка отчётов для публикации | Исходный текст/расшифровка | 3 версии текста | Да |
| Видеоредактор | Подготовка видео к публикации | Видео, транскрипт | План монтажа, субтитры, превью | Да |
| Контролёр приватности | Проверка перед публикацией | Финальный текст/видео | Список рисков/ПД | Нет (блокирующая проверка) |
| Агент упаковки публикации | Сборка финального поста | Текст + видео + метаданные | Черновик поста | Да |
| Агент-издатель | Публикация в канал | Подтверждённый пост | Telegram message ID | Да (уже получено выше) |

Для каждой роли в коде фиксируются: условия запуска, входные данные, доступные инструменты (только необходимые — например, редактор текста не имеет доступа к публикации), формат структурированного ответа (JSON-схема), лимиты токенов/стоимости, правила логирования.

## 6. Связь Telegram-бота, backend и Mini App/PWA

- **Бот**: Telegram Bot API, webhook-режим. Все входящие обновления → backend endpoint `/telegram/webhook`.
- **Backend**: единственная точка бизнес-логики. Bot handler и Mini App вызывают одни и те же сервисные функции/use-case'ы, не дублируют логику.
- **Mini App**: открывается через `WebApp.initData`; backend валидирует подпись `initData` (HMAC по правилам Telegram) на каждый запрос или на выдачу короткоживущей сессии/JWT.
- **PWA**: та же кодовая база фронтенда (Next.js) с манифестом и service worker для установки на экран телефона, офлайн-кеш последнего состояния «Сегодня».

Схема данных: бот и Mini App читают/пишут через один и тот же слой API — никакой прямой записи бота в БД в обход backend-валидации.

## 7. Модуль публикации в закрытый канал

Полный конвейер:

```
Текст / голосовое / видео
        ↓
Сохранение оригинала (Storage, приватно)
        ↓
Расшифровка (для голоса/видео)
        ↓
AI-анализ содержания
        ↓
Редактура текста (3 варианта)
        ↓
Проверка фактов и приватности (блокирующая)
        ↓
Подготовка видео и субтитров (если есть видео)
        ↓
Предварительный просмотр (preview) в Mini App
        ↓
Подтверждение пользователем
        ↓
Публикация ботом в закрытый канал
        ↓
Сохранение поста как доказательства прогресса + Telegram message ID
```

Жёсткое правило: **без явного подтверждения пользователя публикация невозможна**. В базе хранится точная версия текста/видео, которую пользователь видел перед нажатием «Опубликовать» (неизменяемый снапшот, привязанный к message ID).

Дополнительно поддерживаются:
- подключение канала и проверка прав бота (минимально необходимые права — публикация сообщений, без прав администратора сверх нужного);
- тестовая публикация при первичной настройке;
- редактирование уже опубликованного поста (через `editMessageText`/`editMessageMedia`, с сохранением истории версий);
- удаление поста;
- повторная попытка публикации после сетевой/API ошибки (идемпотентно — без дублей);
- защита от повторной публикации одного и того же черновика (idempotency key на уровне задачи публикации).

## 8. Агент редактирования текста

На входе — исходный текст (или расшифровка голосового/видео). На выходе — три версии:

1. **Бережная редактура** — исправление грамматики/пунктуации, сохранение авторского голоса и структуры.
2. **Структурная версия** — более читаемая, с абзацами/акцентами, для основного поста.
3. **Краткая версия** — сжатый вариант для короткого поста/анонса.

Жёсткие ограничения (запрещено агенту):
- придумывать события, факты или детали, которых не было в исходнике;
- менять числа (проценты выполнения, время, даты);
- усиливать/приукрашивать достижения;
- приписывать мысли или слова другим людям;
- превращать честный дневниковый текст в рекламный/маркетинговый;
- публиковать материал самостоятельно (публикация — отдельный шаг с отдельным подтверждением).

UI показывает: исходник, все три варианта, диф значимых изменений, список «неподтверждённых утверждений» (то, что похоже на факт, но не было явно сказано пользователем) и предупреждения о потенциальных персональных данных (имена третьих лиц, адреса, номера и т.д.).

## 9. Агент обработки видео

Конвейер (MVP-объём):

```
Оригинальное видео
    ↓
Проверка формата/длительности + сохранение (Storage)
    ↓
Извлечение аудио
    ↓
Транскрипция с таймкодами
    ↓
Разделение на смысловые блоки
    ↓
Поиск дублей и длинных пауз → предложенный план вырезок
    ↓
Автоматические субтитры
    ↓
Безопасное вертикальное кадрирование 9:16
    ↓
Нормализация громкости + базовое шумоподавление
    ↓
Генерация обложки
    ↓
Короткий preview (низкое разрешение/битрейт)
    ↓
Подтверждение пользователем
    ↓
Финальный рендер (FFmpeg worker)
    ↓
Публикация
```

В MVP **исключено**: сложный кинематографический монтаж (переходы, цветокоррекция), клонирование/синтез голоса, изменение смысла сказанного, автоматическая генерация b-roll.

Технически: транскрипция с таймкодами через ASR-API; модерация текстового и визуального контента перед публикацией (текстовая — обязательна, визуальная — best-effort в MVP); все тяжёлые операции — в фоновом FFmpeg worker с очередью и статусами задачи (`queued → processing → preview_ready → confirmed → rendering → published/failed`).

## 10. Аналитика и метрики

Все метрики вычисляются программно (не AI). AI использует готовые числа для объяснений и гипотез.

Ключевые метрики:
- **Выполнение плана**: доля выполненных главных задач за период.
- **Коэффициент завершения**: (выполнено / запланировано) по всем задачам.
- **Переносы**: сколько раз задача была перенесена, на сколько дней в среднем.
- **Точность оценки времени**: план vs факт по фокус-сессиям.
- **Глубокая работа**: суммарное время фокус-сессий без прерываний.
- **Индекс распыления**: количество параллельно открытых незавершённых направлений/идей.
- **Индекс возвращения**: скорость восстановления цикла после пропуска (дней до возврата к главной задаче).
- **Реалистичность планирования**: соотношение оценённого и фактического времени в динамике.
- **Сон / энергия / настроение / стресс**: из утренних чек-инов, тренд по времени.

Отчёты: недельный, месячный, «Путь 180» (агрегат за весь период), годовой.

## 11. Экраны интерфейса (Mini App/PWA)

1. **Сегодня** — чек-ин, главная задача, доп. задачи, быстрый старт фокуса.
2. **Путь** — прогресс по дням/этапам 180/365, договор с собой, главная миссия.
3. **AI-наставник** — чат с оркестратором, история рекомендаций.
4. **Фокус** — таймер, история сессий, статистика по дням/неделям.
5. **Аналитика** — графики по метрикам из раздела 10, фильтр по периодам.
6. **Дневник** — хронологическая лента записей (текст/голос/видео), поиск.
7. **Студия контента** — черновики постов, статусы конвейера публикации, история публикаций.
8. **Редактор текста** — три варианта, диф, подтверждение.
9. **Видеоредактор** — таймлайн, вырезки, субтитры, preview, подтверждение.
10. **Хранилище идей** — inbox новых мыслей, теги, перенос в задачи.
11. **Настройки** — канал, права бота, уведомления, экспорт/удаление данных.

Для каждого экрана определяются состояния: загрузка, пусто (нет данных), ошибка, офлайн (для PWA — кеш последнего успешного состояния «Сегодня»).

## 12. Модель данных (основные сущности)

- **users** — Telegram ID, профиль, дата Дня 0, длительность программы (180/365).
- **missions** — главная цель, направления, статус.
- **milestones** — этапы плана 180/365.
- **daily_plans** — план на конкретный день (главная задача + доп. задачи, чек-ин).
- **tasks** — атомарные задачи, статус, перенос, оценка/факт времени.
- **focus_sessions** — старт/стоп, привязка к задаче, длительность.
- **evidences** — доказательства выполнения (текст/голос/видео), ссылка на задачу.
- **journal_entries** — записи дневника (может пересекаться с evidences).
- **ideas** — хранилище идей/inbox.
- **skills_map** — направления развития и их прогресс.
- **content_drafts** — черновики постов (текст/видео), стадия конвейера.
- **content_versions** — снапшоты версий текста/видео на каждом шаге (для точного «что видел пользователь перед публикацией»).
- **publications** — опубликованные посты, Telegram message ID, канал, статус.
- **ai_logs** — журнал всех вызовов AI-ролей (роль, вход, выход, стоимость, время).
- **notifications** — история и статус отправленных уведомлений.
- **privacy_flags** — записи, исключённые из AI-памяти пользователем.

Ограничения: внешние ключи на `user_id` везде; `content_versions` — неизменяемые (append-only); `ai_logs` — append-only, retention политика настраивается.

## 13. API backend (сводно)

Группы эндпоинтов:
- `POST /telegram/webhook` — приём обновлений от Telegram.
- `POST /auth/miniapp` — валидация `initData`, выдача сессии.
- `GET/POST /plans/*`, `/tasks/*`, `/focus-sessions/*` — ежедневный цикл.
- `POST /evidences` — загрузка отчётов (текст/голос/видео).
- `GET /analytics/*` — метрики и отчёты.
- `GET/POST /journal/*`, `/ideas/*`, `/skills/*`.
- `POST /content/drafts`, `POST /content/drafts/:id/edit`, `POST /content/drafts/:id/confirm`, `POST /content/drafts/:id/publish`.
- `GET/POST /settings/*`, `POST /privacy/export`, `POST /privacy/delete`.

Стандарт ответов: единый формат ошибок (`code`, `message`, `details`), стандартные HTTP-коды, идемпотентность через `Idempotency-Key` для операций публикации и списания AI-стоимости.

## 14. Фоновые задачи и очереди

Очередь для: транскрипции, генерации трёх версий текста, обработки видео (по шагам конвейера), публикации в канал, генерации отчётов аналитики за большие периоды.

Требования: идемпотентность по `Idempotency-Key`/`draft_id`; retry с экспоненциальной задержкой и ограничением попыток; статус задачи, доступный клиенту (poll или webhook/событие в Mini App); dead-letter обработка для задач, исчерпавших retry.

---

## 15. Безопасность и приватность

- Серверная проверка `initData` Telegram (HMAC-подпись) — обязательна для всех запросов Mini App.
- Приватное хранение дневников и видео, доступ только владельцу.
- Временные (подписанные, с истечением) ссылки на файлы в Storage.
- Row Level Security (RLS) на уровне БД — каждый пользователь видит только свои данные.
- Минимальные права бота в закрытом канале (только публикация, без лишних админ-прав).
- Журнал всех AI-действий и публикаций (`ai_logs`, `publications`) для аудита.
- Экспорт всех данных пользователя по запросу.
- Полное удаление данных по запросу (с каскадным удалением файлов из Storage).
- Возможность исключить конкретную запись из AI-памяти/контекста (`privacy_flags`), не удаляя её физически, если пользователь хочет сохранить запись, но не хочет, чтобы AI её использовал.

## 16. Технический стек (рекомендуемый)

- **Frontend (Mini App/PWA)**: Next.js (единая кодовая база для Mini App и PWA, встроенный сценарий PWA), Telegram WebApp SDK.
- **Backend**: Node.js/TypeScript API-сервер.
- **База данных**: Postgres (рекомендуется Supabase — встроенные RLS и Storage с политиками доступа).
- **Очереди/фон**: воркеры на очереди задач (например, на основе Postgres-очереди или отдельного брокера), отдельный FFmpeg worker для видео.
- **AI**: Anthropic API (Claude) как оркестратор ролей; ASR-провайдер для транскрипции с таймкодами.
- **Хранилище файлов**: Supabase Storage (или совместимый S3-подобный сервис) с приватными бакетами и временными ссылками.
- **Бот**: Telegram Bot API в режиме webhook.

## 20. План релизов и критерии приёмки

### Release 1 — «Начать путь» (ядро Telegram-бота)
Объём: онбординг, День 0, договор с собой, главная цель, задачи на день, приём отчётов, AI-разбор, формирование плана на завтра, хранилище идей (без переключения), базовая подготовка поста для канала (без полного конвейера публикации).
Критерий приёмки: пользователь может провести полный дневной цикл только через бота, без Mini App.

### Release 2 — «Увидеть путь» (Mini App + PWA)
Объём: экраны «Сегодня», «Путь», AI-наставник (чат), аналитика (базовые метрики), дневник, карта навыков, хранилище идей с UI.
Критерий приёмки: все данные, накопленные ботом в Release 1, видны и редактируемы в Mini App; установка как PWA работает.

### Release 3 — «Показать результат» (редактор текста + публикация)
Объём: полный конвейер публикации текста (раздел 7–8), контролёр приватности, студия контента.
Критерий приёмки: публикация в закрытый канал происходит только после явного подтверждения, снапшот версии сохраняется корректно.

### Release 4 — «Собрать историю» (видео)
Объём: полный конвейер обработки видео (раздел 9), интеграция с публикацией.
Критерий приёмки: видео проходит весь конвейер до preview и публикуется только после подтверждения; субтитры и вертикальный формат корректны.

Правило для AI-кодера: **не начинать реализацию следующего релиза, пока текущий не прошёл критерий приёмки.**

|---|---|---|
