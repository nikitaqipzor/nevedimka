# План запуска «Невидимка»

Цель этого документа — не «ещё раз описать архитектуру», а провести за руку
от чистого архива до момента, когда вы пишете боту `/start` в Telegram и
видите, как всё это работает вживую. Дальше — короткая экскурсия по
функциям всех четырёх релизов, чтобы попробовать по-настоящему всё, а не
только ядро.

Реальное время: 15–20 минут до первого рабочего диалога с ботом. Остальное
(Mini App, видео) — по желанию, отдельными блоками ниже.

---

## Production через Docker Compose

Этот блок — актуальный путь запуска. Секции ниже описывают локальную разработку; их пример с одной Postgres-ролью нельзя переносить в production.

1. Установите Node.js 22+ и Docker Compose. Из `nevidimka/` выполните `npm ci` и `cp .env.example .env`.
2. Заполните токен бота, owner ID, ключ Anthropic, `JWT_SECRET`, публичный `APP_BASE_URL`, два независимых Compose-пароля. Секреты генерируйте `openssl rand -hex 32`; не отправляйте их в чат или git.
3. Для polling оставьте webhook пустым. Для webhook задайте HTTPS URL `/telegram/webhook` и отдельный секрет. Все тестовые API override и dev auth оставьте пустыми.
4. Настройте HTTPS reverse proxy: web на loopback-порту 3000, bot webhook на 3001. Postgres привязан к loopback. Compose задаёт общие storage-тома и отдельные DB-роли автоматически.
5. Дождитесь зелёного root CI. При необходимости локально выполните `npm run smoke:compose`: он использует временный проект и фиктивные внешние ключи.
6. Выполните `docker compose up -d --build`, затем `docker compose ps -a` и `docker compose logs --tail=100 bot worker web`. Миграции и bootstrap должны завершиться с кодом 0.
7. Из каталога с заполненным `.env` после `npm run build` выполните `npm run smoke:integrations`. Он читает настройки Telegram и делает маленький платный запрос Anthropic; webhook не меняет. Опциональный ASR: `npm run smoke:integrations -- --asr /path/to/test.ogg`.
8. Откройте Mini App из Telegram владельца, проверьте ежедневный цикл и тестовую публикацию. Webhook-проверка через API не заменяет реальную доставку сообщения от Telegram.

Для внешнего Postgres необходимы обе URL с разными ролями; `DATABASE_URL` должен быть `NOSUPERUSER NOBYPASSRLS`, системная роль должна обходить RLS. Миграции выполняются системной ролью. Подробнее — `LAUNCH_CHECKLIST.md` и `SECURITY.md`.

## Шаг 0 — Что подготовить заранее

Нужно четыре вещи. Каждая — 2-3 минуты.

### 1. Токен Telegram-бота
В Telegram найдите **@BotFather** → `/newbot` → дайте имя (например,
«Невидимка») и username, оканчивающийся на `bot` (например,
`nikita_nevidimka_bot`). BotFather пришлёт токен вида
`123456789:AAH...` — это `TELEGRAM_BOT_TOKEN`.

### 2. Ваш личный Telegram ID
Напишите **@userinfobot** в Telegram — он мгновенно ответит вашим numeric
ID. Это `OWNER_TELEGRAM_ID`. **Не пропускайте этот шаг** — без него production-бот
откажется запускаться (см. `AUDIT_REPORT.md`, раздел
про контроль доступа).

### 3. Ключ Anthropic API
На [console.anthropic.com](https://console.anthropic.com) → API Keys →
Create Key. Это `ANTHROPIC_API_KEY`.

### 4. База данных Postgres — один из трёх вариантов

**Вариант А — бесплатный хостинг, без установки чего-либо (проще всего):**
Зарегистрируйтесь на [neon.tech](https://neon.tech) или
[supabase.com](https://supabase.com), создайте проект, скопируйте
connection string (вида `postgres://user:pass@host/dbname`). Готово, это
`DATABASE_URL`.

**Вариант Б — Docker, если он у вас уже есть:**
```bash
docker run --name nevidimka-db -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=nevidimka -p 5432:5432 -d postgres:16
```
`DATABASE_URL=postgres://postgres:postgres@localhost:5432/nevidimka`

**Вариант В — Postgres локально (apt/brew):**
```bash
# Ubuntu/Debian
sudo apt install postgresql && sudo -u postgres createdb nevidimka
# macOS
brew install postgresql@16 && createdb nevidimka
```

## Шаг 1 — Установка

```bash
unzip nevidimka-release1-2-3-4.zip
cd nevidimka
npm ci
cp .env.example .env
```

Откройте `.env` и заполните четыре значения из Шага 0:

```
TELEGRAM_BOT_TOKEN=<токен от BotFather>
OWNER_TELEGRAM_ID=<ваш ID от @userinfobot>
ANTHROPIC_API_KEY=<ключ Anthropic>
DATABASE_URL=<connection string из Шага 0.4>
JWT_SECRET=<любая случайная строка — можно сгенерировать: openssl rand -hex 32>
```

Остальные переменные в `.env.example` уже имеют разумные значения по
умолчанию — трогать не нужно для первого запуска.

## Шаг 2 — Применить миграции

```bash
npm run db:migrate
```

Должно вывести пять строк `apply 00X_....sql` и `Migrations up to date.`
Если ошибка про доступ/пароль — перепроверьте `DATABASE_URL`.

## Шаг 3 — Запустить бота

```bash
npm run dev:bot
```

Вывод должен закончиться строкой вида
`Nevidimka bot starting in long-polling mode...`. Бот запущен и слушает
Telegram. Оставьте это в терминале открытым.

## Шаг 4 — Экскурсия: попробуйте всё, что мы построили

Откройте Telegram, найдите своего бота по username и начните.

### Release 1 — ядро и ежедневный цикл

```
/start
```
Пройдите онбординг: День 0 → договор с собой (напишите пару честных
предложений) → главная цель → длительность пути (180 или 365) →
направления. На последнем шаге AI-стратег сформулирует миссию и этапы —
это первый настоящий вызов Claude в этом сеансе.

После онбординга внизу чата появится постоянная клавиатура с кнопками
(`/today`, `/idea`, `/evening`, `/post`, `/video`, `/settings`) — не нужно
печатать команды руками. Также доступно нативное меню Telegram: нажмите
значок «/» рядом с полем ввода — там весь список команд с описаниями.

```
/settings
```
Сразу после онбординга стоит настроить часовой пояс (IANA-формат, например
`Europe/Moscow`) и часы утреннего/вечернего напоминания — без этого бот
никогда не напишет первым (см. `AUDIT_REPORT.md`: это была реальная, только
что найденная и исправленная недоработка — cron-джобы были готовы, но
включить их было физически нечем).

```
/today
```
Ответьте на чек-ин (четыре числа 1-5: сон энергия настроение стресс,
например `4 3 4 2`). AI-планировщик соберёт план дня с учётом этого. Под
главной задачей — кнопки: нажмите **«Начать фокус»**, подождите пару
секунд, нажмите **«Завершить фокус»**. Затем **«Отчитаться»** и напишите
пару слов о том, что сделано — AI-ревьюер оценит процент выполнения.

```
/idea
```
Сохраните любую мысль — она уйдёт в хранилище, не прерывая текущую задачу.

```
/evening
```
Итог дня и короткая рефлексия.

### Release 3 — публикация текста (нужен канал)

Создайте закрытый Telegram-канал, добавьте своего бота администратором с
правом публикации сообщений, узнайте ID канала (перешлите любое сообщение
из канала боту [@getidsbot](https://t.me/getidsbot), либо возьмите
`@username_канала`, если он публичный) и впишите в `.env`:
```
TELEGRAM_CHANNEL_ID=<@username или -100...>
```
Перезапустите бота (`Ctrl+C`, затем снова `npm run dev:bot`), затем:
```
/post
```
Бот предложит собрать пост из недавней записи или нового текста, покажет
три AI-версии (бережная / структурная / краткая), даст выбрать или
написать свою, покажет предупреждения о приватности, если найдёт — и
опубликует только после явного нажатия «Опубликовать».

### Release 4 — видео (нужны ffmpeg и отдельный воркер)

```bash
# в новом терминале
sudo apt install ffmpeg   # или brew install ffmpeg на macOS
npm run --workspace=apps/worker dev
```
Оставьте воркер работать в этом терминале. В боте:
```
/video
```
Пришлите видео до 3 минут. Воркер вырежет длинные паузы, приведёт к
вертикальному формату 9:16, нормализует звук, соберёт превью — и напишет
вам, когда всё готово (обычно 10-30 секунд для короткого ролика). Наберите
`/video` ещё раз, чтобы увидеть превью и подтвердить публикацию.

**Опционально — расшифровка речи.** Впишите `ASR_API_KEY` (ключ OpenAI) в
`.env` — тогда опубликованное видео получит настоящие субтитры, а
голосовые/видео-отчёты будут расшифровываться автоматически вместо
просьбы напечатать резюме. Без этого ключа всё остальное работает точно
так же, просто без транскрипта. Честно: эта конкретная интеграция
проверена только против мок-сервера (см. `README.md`), не против
настоящего OpenAI API — первая транскрипция после того, как впишете свой
ключ, будет первой реальной проверкой.

## Шаг 5 (опционально) — Mini App

Для полноценного просмотра внутри Telegram нужен публичный HTTPS-адрес.
Быстрее всего — через туннель для локальной разработки:

```bash
# в новом терминале
npm run --workspace=apps/web dev
# в ещё одном терминале — быстрый HTTPS-туннель, например:
npx ngrok http 3000
```
`ngrok` выдаст адрес вида `https://xxxx.ngrok-free.app`. Впишите его в
`.env` как `APP_BASE_URL`, перезапустите `apps/web`. Затем у @BotFather:
`/mybots` → выберите бота → Bot Settings → Menu Button → впишите этот
HTTPS-адрес. В чате с ботом появится кнопка меню, открывающая Mini App —
экраны «Сегодня», «Путь», «AI-наставник», «Студия контента», «Аналитика»,
«Карта навыков», «Дневник», «Идеи».

Без Telegram можно посмотреть и в обычном браузере на `http://localhost:3000`
— сработает dev-заглушка авторизации на `OWNER_TELEGRAM_ID`.

## Шаг 6 (опционально) — через Docker вместо ручных команд

Если не хочется поднимать Postgres/бота/воркер отдельными командами:

```bash
cp .env.example .env
# заполнить .env — важно: DATABASE_URL должен указывать на сервис "postgres"
# по имени, а не localhost:
#   DATABASE_URL=postgres://postgres:postgres@postgres:5432/nevidimka
docker compose up --build
```

Поднимет Postgres, применит миграции (отдельный шаг `migrate`, выполняется
один раз перед стартом остальных сервисов) и запустит бота, воркер и
Mini App (`http://localhost:3000`) вместе, с `restart: unless-stopped`.

**Честно**: `Dockerfile` и `docker-compose.yml` написаны и тщательно
вычитаны (все пути и команды сверены с тем, что реально проверено в этом
репозитории), но ни разу не собирались через настоящий `docker build` —
в среде, где это писалось, не было доступа к Docker. Первый реальный
`docker compose up --build` — это и есть первая настоящая проверка;
если что-то не сойдётся — скорее всего мелочь в путях COPY.

## Если что-то не заработало

- **Бот не отвечает** — проверьте, что терминал с `npm run dev:bot` не
  выдал ошибку при старте, и что `OWNER_TELEGRAM_ID` в `.env` совпадает с
  тем, что ответил @userinfobot (без пробелов и `@`).
- **AI не отвечает / ошибка про ANTHROPIC_API_KEY** — ключ не вписан или
  на счету Anthropic нет доступных кредитов.
- **Ошибка миграций про пароль/доступ** — `DATABASE_URL` неверный или база
  ещё не создана.
- **Видео не обрабатывается** — воркер (`apps/worker`) должен быть
  отдельно запущен и работать всё время, пока вы им пользуетесь; сам бот
  ffmpeg не запускает.

## Перед тем, как пользоваться регулярно

Всё выше — чтобы почувствовать продукт. Прежде чем полагаться на него
каждый день, откройте `AUDIT_REPORT.md` — там чек-лист (роль Postgres без
`BYPASSRLS` кроме документированного случая, реальный `JWT_SECRET` и т.д.)
и честный список того, что ещё не сделано (down-миграции, retry не для
всех сценариев отказа воркера при очень долгих сбоях сети и т.п.). Для
личного разового использования уже сейчас всё безопасно и работает — чек-
лист про то, что стоит проверить перед тем, как встроить это в
повседневную жизнь надолго.
